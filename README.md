# Дом Климата — вёрстка сайта

Статическая вёрстка (HTML/CSS/JS) под последующую натяжку на WordPress.
Текущий сайт: https://domklimata59.ru/

## Запуск

Открывать **только через Live Server** (или любой локальный http-сервер):
секции подгружаются через `fetch`, по `file://` браузер их заблокирует.

В VS Code: правый клик по `index.html` → Open with Live Server.
Порт задан в `.vscode/settings.json` (5505).

## Структура

```
index.html                 — главная: каркас и плейсхолдеры секций
404.html                   — страница «не найдено» (пути от корня)
css/
  styles.css               — главный файл: подключает базу и все секции
  reset.css                — сброс
  fonts.css                — @font-face (Onest, локально)
  base.css                 — переменные, типографика, .container, .button, поля
  icons.css                — иконки: .icon--<имя> → img/icons/<имя>.svg
  request-form.css         — форма заявки (CTA + модалка)
js/
  include-sections.js      — сборка страницы из HTML-секций, {{root}}
  app.js                   — общие скрипты (после события sections:loaded)
sections/
  <секция>/<секция>.html   — разметка секции
  <секция>/<секция>.css    — стили секции (БЭМ-блок = имя папки)
img/
  icons/                   — иконки Tabler Icons (MIT), по файлу на иконку
  brands/ categories/ photos/
fonts/
```

## Новая страница

Страница лежит в папке с адресом будущего URL: `/about/` → `about/index.html`.

```html
<link rel="stylesheet" href="../css/styles.css">
<body data-root="../">
  <div data-include="../sections/header/header.html"></div>
  <main id="main">…</main>
  <div data-include="../sections/footer/footer.html"></div>
  <div data-include="../sections/request-modal/request-modal.html"></div>
  <div data-include="../sections/cookie/cookie.html"></div>
  <script src="../js/include-sections.js"></script>
  <script src="../js/app.js"></script>
</body>
```

`data-root` — путь до корня сайта. Внутри секций все пути пишутся через
`{{root}}` (`{{root}}img/logo.webp`), скрипт подставит нужный префикс,
поэтому одна секция работает на любой глубине вложенности.

Адреса в меню повторяют адреса текущего сайта (`/catalog/…`, `/Installation/`,
`/dostavka-i-oplata/`, `/kontakty/` и т. д.), чтобы не потерять страницы
при переезде. Пока эти страницы не свёрстаны, Live Server отдаст по ним 404.

## Новая секция

1. Папка `sections/<имя>/` с файлами `<имя>.html` и `<имя>.css`.
2. Плейсхолдер на странице: `<div data-include="sections/<имя>/<имя>.html"></div>`.
3. `@import url("../sections/<имя>/<имя>.css");` в `css/styles.css`.

## Соглашения

- CSS по БЭМ: блок = имя секции (`.services`), элемент `.services__feature`,
  модификатор `.category--main`.
- Цвета, отступы, скругления — только через переменные из `base.css`.
- Цвет бренда — петроль из логотипа `#014454`. Акцент — оранжевый `#f26b2e`,
  только для кнопки заявки и активных состояний. Текст на оранжевом тёмный
  (белый не проходит контраст).
- Скругления: 10px кнопки и поля, 16px карточки, 24px крупные панели.
- Иконки: `<span class="icon icon--phone" aria-hidden="true"></span>`, цвет
  берётся из `color`. Новая иконка: SVG с tabler.io/icons в `img/icons/`
  и строка `.icon--имя { --icon: url(...) }` в `css/icons.css`.
- **Во фрагментах секций не писать `<svg>…</svg>` (и `</body>`).** Live Server
  вставляет свой скрипт автообновления перед каждым `</svg>` в отдаваемом
  HTML-файле, а `Content-Length` увеличивает только на одну вставку —
  браузер обрезает конец секции, падают скрипты и не появляется контент.
  Нужна SVG-графика — отдельным файлом через `<img>` или CSS.
- Анимации уважают `prefers-reduced-motion`. Появление при прокрутке —
  атрибут `data-reveal` (+ `style="--reveal-index: N"` для очерёдности).

## Главная

Порядок секций: первый экран → подбор оборудования → каталог → монтаж
и сервис → преимущества → бренды → FAQ → заявка.

- **Подбор** (`initSelection`): тип помещения, площадь, число комнат →
  тип оборудования, мощность, типоразмер, ссылка на категорию. Ориентир:
  0,1 кВт/м² для жилья, 0,12 кВт/м² для офиса и магазина. Итог подбора
  подставляется в комментарий заявки.
- **Заявка**: одна форма в секции CTA и в модалке (кнопки `[data-open-request]`).
  Проверка полей, маска телефона, состояния «отправка», «успех», «ошибка».
  Отправки на сервер нет: функция `sendRequest` в `app.js` — место для
  обработчика WordPress (Contact Form 7 / admin-ajax).
- **Поиск в шапке**: форма отправляет стандартный WordPress-запрос `?s=`.
  Подсказки — готовый список популярных разделов, не живой поиск.

## Каталог (/catalog/)

Одна страница на весь каталог. Категория, фильтры и сортировка — параметры
адреса, отдельных подстраниц категорий нет:

```
/catalog/                                         все товары
/catalog/?category=bitovie_konditsioneri           категория
/catalog/?category=bitovie_konditsioneri&brand=Axioma&brand=Bosch&area=35
         &inverter=yes&stock=price&price_from=20000&price_to=60000&sort=price-asc
```

| Параметр | Значения |
|---|---|
| `category` | `bitovie_konditsioneri`, `multisplit_sistemi`, `polupromishlennie_konditsioneri`, `mobilnie_konditsioneri`, `okonnie_konditsioneri`, `ventilyatsiya`, `otoplenie`, `aksessuari` |
| `brand` | название бренда, можно несколько |
| `area` | площадь модификации, м², можно несколько |
| `inverter` | `yes` / `no` |
| `stock` | `price` (цена на сайте) / `order` (под заказ) |
| `price_from`, `price_to` | рубли |
| `sort` | `price-asc`, `price-desc` (по умолчанию не пишется) |

- Имена параметров = имена полей формы `#catalog-filter-form`: без скрипта
  форма уходит обычным GET, на WordPress сервер читает те же параметры.
- В вёрстке фильтрует `initCatalog` в `app.js`: читает адрес при загрузке,
  фильтры пишет через `replaceState`, смену категории — через `pushState`
  («Назад» возвращает к прошлой категории). Заголовок, описание, крошки
  и `<title>` берутся из `data-title` / `data-text` ссылки в `.cat-nav`.
- Смена категории сбрасывает фильтры, «Сбросить все» оставляет категорию.
- Вид (плитка / список) — настройка браузера, хранится в localStorage.
- Ссылки с главной, из меню, подвала и поиска ведут сразу на нужный набор:
  «До 35 м²» → `?category=bitovie_konditsioneri&area=35`, подбор по площади
  → категория и площадь подходящей модификации.

Товары — снимок текущего сайта, по нескольку позиций из каждой категории
(27 шт.): названия, модели по площадям, цены, статусы, фото в `img/products/`.
Признак «Инвертор» проставлен по названию. Карточка товара — общий компонент
`css/product-card.css`: выбор площади меняет модель, цену и статус; есть цена —
«В корзину», нет — «Узнать цену» с моделью в комментарии заявки. Корзина
и избранное в вёрстке только меняют состояние и счётчик в шапке.

## Товар (/catalog/product/<слаг>/)

Пример: `catalog/product/asx07h1r/` — Axioma Серия H R32 (данные, фото,
характеристики и похожие товары со страницы этого товара на текущем сайте).
На WordPress — шаблон single-product.

- `pr-main` — крошки, галерея (миниатюры, стрелки, свайп, увеличение
  в `<dialog>` со стрелками ← →), заголовок, плитки характеристик, блок
  покупки с выбором площади, «Что входит в монтаж».
- `pr-specs` — характеристики группами и условия доставки и оплаты.
- `pr-similar` — похожие товары, компактная карточка `.product-mini`
  (`css/product-card.css`). На телефоне ряд листается вбок.
- Площадь (модификация) — параметр `?area=25`, как фильтры каталога.
  Карточки каталога передают выбранную площадь в ссылку на товар.
  Данные модификаций — в data-атрибутах радиокнопок `.pr-buy__sizes`
  (на WordPress — вариации). Неизвестное значение → первая модификация.
- «Заказать монтаж» открывает заявку с моделью и площадью в комментарии.
  «В корзину» в вёрстке меняет кнопку и счётчик в шапке
  (`initProductPage`, `initGallery`, `initMiniCart` в `app.js`).

## Корзина (/cart/)

Корзина и оформление на одной странице (секция `cart`, `initCart` в `app.js`).
Товары — корзина со скриншота текущего сайта.

- Количество «−/+» и ввод с клавиатуры (1-99), сумма строки и «N ₽ за шт.».
- Удаление с отменой: всплывашка «Вернуть» 6 секунд. Последний удалённый
  товар → пустая корзина, отмена её возвращает.
- Доставка по Перми бесплатна от 20 000 ₽, иначе 1 000 ₽ (условия сайта);
  ниже порога подсказка, сколько добавить. Самовывоз из офиса бесплатный.
- Монтаж — галочка без цены: стоимость считает менеджер. Промокод уходит
  в заказ, проверка на сервере.
- Форма: имя, телефон, e-mail (необязательно), получение, адрес (для доставки),
  оплата, комментарий, согласие. Ошибки под полями, фокус на первое неверное.
  Количества, монтаж, промокод и согласие стоят вне `<form>`, но привязаны
  к ней атрибутом `form="checkout-form"` и уходят вместе.
- На телефоне снизу панель «Итого + Оформить», пока кнопка в сводке ниже экрана.
- Счётчик в шапке на этой странице = сумма количеств. «В корзину» на других
  страницах в вёрстке эту корзину не наполняет (на WordPress — WooCommerce).

## Личный кабинет (/personal/profile/)

Один адрес на вход, восстановление пароля, регистрацию и профиль, как на
текущем сайте. Секции `auth` и `account`, `initAuth` в `app.js`.

| Адрес | Что показано |
|---|---|
| `/personal/profile/` | вход (или профиль, если пользователь вошёл) |
| `?forgot_password=yes` | восстановление пароля |
| `?register=yes` | регистрация |
| `?section=personal|work|orders` | раздел профиля |

- Поля форм как на текущем сайте (имена Битрикса: `USER_LOGIN`, `USER_PASSWORD`…).
  В регистрацию добавлено согласие на обработку персональных данных.
- В вёрстке сервера нет: вход и регистрация с любыми данными «входят»
  через отметку в sessionStorage, «Выйти» её снимает. На WordPress
  это решает сервер.
- Профиль: регистрационная информация (последний вход, обращение, ФИО,
  логин, email, смена пароля в модалке), личные данные, информация о работе,
  история заказов. Значения полей и заказы — пример для вёрстки; после
  регистрации личные данные пустые.
- Пароль с кнопкой «Показать» — общий компонент `css/password.css`.
- Иконка личного кабинета в шапке рядом с корзиной.

## На WordPress

Каждая секция переносится в `template-parts/section-<имя>.php` один в один,
`{{root}}` заменяется на `get_template_directory_uri()` / `home_url()`.
Тексты, цифры, оценки на площадках, условия доставки и оплаты взяты
с текущего сайта как снимок — сверить перед запуском.

## Изображения

- Hero: три слайда «Климат для дома», «Монтаж под ключ», «Подбор техники».
  `hero-comfort.webp` и `hero-comfort-mobile.webp` созданы встроенным imagegen:
  естественная интерьерная фотография обычной квартиры с кондиционером,
  серым диваном и дневным светом, без текста и рекламных спецэффектов.
  Это иллюстрация, а не фотография выполненного объекта.
  Для второго и третьего слайдов использованы реальные фото старого сайта:
  `installation.webp` и `maintenance.webp`.
- Hero: горизонтальное перелистывание, две стрелки по краям панели, клавиши
  ←/→ и свайпы. Подписи и нижняя панель удалены. Автосмена каждые 7 секунд
  продолжается после ручного переключения. Пауза при чтении текста мышью,
  фокусе на содержимом, скрытии вкладки и уходе hero с экрана.
  При `prefers-reduced-motion` автосмена отключена.
- `img/photos/hero-interior*.webp` — интерьер первого экрана сгенерирован
  нейросетью, это иллюстрация, а не фото объекта. Лучше заменить на реальную
  съёмку.
- `img/photos/installation.webp` и остальные фото — из блога текущего сайта.
- `img/categories/*`, `img/brands/*`, логотип — с текущего сайта.

## Внутренние страницы

- `/ventilyatsiya/`: все пять услуг, четыре этапа работы, восемь преимуществ и четыре кейса.
- `/Installation/`: установка в два этапа и стандартный монтаж с составом
  работ и материалов, 14 разделов дополнительного прайса (68 строк),
  фотографии монтажа и шесть кейсов.
- `/about/`: описание компании, шесть сертификатов с увеличением,
  девять изображений галереи, три новости, сотрудничество с дизайнерами.
- Общие стили внутренних страниц: `css/pages.css`; настройка Fancybox и аккордеона:
  `js/pages.js`; форма с e-mail и типом помещения: `sections/page-request/`.
- Тексты, цены и изображения перенесены с соответствующих страниц старого
  сайта 26.10.2026. Источники изображений: `img/content/sources.json`.
  Ссылки кейсов и новостей ведут на исходные публикации, пока эти разделы
  не перенесены. Названия и цены строк прайса сохранены как в источнике,
  включая повторы и неоднозначную строку наружного блока за 9 500 ₽.
- Формы используют существующий демонстрационный обработчик `sendRequest`.
  Подключение реальной отправки выполняется при интеграции с CMS.

## Навигация и лайтбокс

- На компьютере бургер справа появляется, когда верхняя навигация уходит
  за экран, и скрывается при возврате наверх. На телефоне, где верхней
  навигации нет, бургер доступен сразу. Панель содержит страницы, каталог
  и контакты. Закрытие по Esc,
  повторному нажатию, ссылке и клику снаружи; фокус удерживается в навигации.
- Раскрытие FAQ и монтажных блоков анимируется за 420 мс через Web Animations API.
  В прайсе и FAQ открыт один пункт группы. В HTML сохранён нативный `name`
  для работы без JS; при инициализации управление группой переходит к JS,
  чтобы закрытие не обрывало анимацию. Быстрые повторные клики поддерживаются.
  При reduced motion раскрытие происходит сразу.
- Только фотогалереи используют Fancybox 6.1.14, как в примере Карповки.
  Изображения вписываются в экран без внутренней прокрутки. Доступны стрелки,
  свайпы, миниатюры и Esc. Сертификаты открываются независимо в нативном
  `dialog`: один документ, затемнение, подпись и кнопка закрытия, без галереи.
- Hero поддерживает горизонтальные жесты тачпада (`wheel` с `deltaX`).
  Порог 40 px и блокировка инерции дают один слайд за жест. Вертикальный скролл
  и pinch-to-zoom не перехватываются. На телефонах доработаны все первые экраны,
  в том числе отдельный компактный режим при высоте до 660 px.
- Библиотека сохранена локально в `vendor/fancybox/`, источник:
  https://cdn.jsdelivr.net/npm/@fancyapps/ui@6.1.14/ . Условия использования:
  `vendor/fancybox/LICENSE.md`; для коммерческой публикации нужна подходящая
  лицензия Fancyapps. Лицензия не приобреталась в рамках этой задачи.
